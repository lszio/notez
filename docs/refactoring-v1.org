#+title: Notez 第一版可用化重构设计
#+date: 2026-08-26
#+STARTUP: showeverything

本文是 Notez 面向第一版可用产品的重构设计。它吸收 [[file:references/silverbullet.org][SilverBullet]] 与 [[file:references/silverbullet-sliq.org][SLIQ]] 的经验，但不直接复制其「厚客户端、哑服务端」架构。本文覆盖两个第一版硬要求：

1. 本地 Markdown / Org 文档可以阅读、搜索和编辑；
2. Janet 作为受限的动态查询与渲染运行时可用。

当前实现状态与历史问题见 [[file:current-architecture-and-redesign.md][当前架构与整体重设计评审]]；长期目标态见 [[file:architecture-v2.org][架构 v2 重设计]]。本文优先级高于旧路线图中与本文冲突的 MVP 顺序，直到实现完成后再回写 =roadmap.org=。

* 1. 决策摘要

** 1.1 产品定义

> Notez 是一个本地优先的文档工作区。它挂载一个或多个文档源，统一提供阅读、搜索、编辑、结构化查询和动态渲染；一个 Notez 实例也可以作为另一个实例的远程文档源。

第一版必须完成一条闭环：

#+begin_src text
本地 Markdown / Org 文件
        |
        v
Source Adapter -> Document Model -> Projection / Query
        |                              |
        +----------+-------------------+
                   |
                   v
        Dispatcher / Protocol
          |       |       |
         Web     CLI     MCP
                   |
                   v
          Janet Query / Render
#+end_src

** 1.2 核心取舍

- 原始 Markdown / Org 文件是本地源的事实来源；SQLite、对象索引和 Janet 结果都是可重建或可丢弃的派生数据。
- 第一版支持编辑，但编辑必须经过统一写入管道；Web、CLI、MCP 不得各自直接修改文件。
- 第一版支持 Janet，但 Janet 默认是只读、受限、可超时的查询与渲染运行时；它不是第二套文件写入 API。
- Source 能力显式声明。读取、搜索、局部补丁、整文件写入、监听和脚本执行不是一个布尔值。
- Notez 实例实现 Remote Notez Source 协议，但第一版远程实例只读。
- Markdown 第一版提供完整读写闭环；Org 第一版提供阅读、搜索和受限结构化写回，无法保证未识别语法的完美格式保留时必须拒绝该写入。
- CLI、Web、MCP 只做协议翻译和呈现；领域规则、能力检查、revision 检查和错误分类集中在 Engine。
- Desktop / Mobile 不在第一版独立实现领域逻辑；后续复用同一 Protocol 和客户端状态模型。

** 1.3 明确非目标

第一版不实现：

- 多人实时协作或 CRDT；
- Notion / Anytype 双向写入；
- 任意 Janet 脚本访问文件系统、网络、进程或 Rust 内部对象；
- 完整 SilverBullet SLIQ 语法兼容；
- 任意 Org/Babel 语法的无损结构化编辑；
- 远程 Source 的分布式事务；
- 通过复制正文解决跨 Space / 跨 Source 组合；
- 每个平台单独维护一套领域模型。

* 2. 第一版验收闭环

** 2.1 本地工作区

以下流程必须在一个真实目录中完成：

#+begin_src sh
notez serve ./workspace
#+end_src

用户可以：

1. 打开 Web 并看到已配置的本地 Source；
2. 浏览 Markdown 与 Org 文件；
3. 打开文档并查看原文和解析后的标题、标签、任务、链接；
4. 搜索文件名、标题、正文、标签和任务；
5. 编辑 Markdown 并保存到原文件；
6. 编辑 Org 支持的结构化字段，并保存为文本补丁；
7. 用外部编辑器修改文件后，让 Notez 重新读取并更新投影；
8. CLI 查询和读取结果与 Web 使用同一 Engine；
9. MCP 查询和读取结果与 CLI/Web 使用同一 Engine；
10. 文件格式中未被 Notez 识别的内容不会被静默删除或重排。

** 2.2 Janet 动态内容

在文档中提供受限的 Janet 查询或渲染块，例如：

#+begin_src text
#+begin_src janet :mode query
(def rows (notez/search {:tag "project" :limit 10}))
(notez/render-list rows)
#+end_src
#+end_src

具体文档语法可在实现阶段冻结，但必须满足以下行为：

- 脚本可以读取显式暴露的查询 API；
- 脚本返回结构化值或受支持的渲染值；
- 脚本超时、异常、返回值类型错误时，页面显示结构化错误而不是整个文档失败；
- 默认不能读取任意路径、访问网络、启动进程或修改文档；
- 每次执行带有 source、document、actor、revision 和 trace 标识；
- Janet 不绕过 Dispatcher 写文件；
- 相同输入 revision 和相同脚本版本得到可复现结果，除非显式调用非确定性 API。

** 2.3 远程 Notez Source

第一版允许当前实例挂载一个远程 Notez 实例：

#+begin_src toml
[[sources]]
id = "local"
kind = "markdown"
root = "./workspace"

[[sources]]
id = "upstream"
kind = "notez-rest"
url = "http://localhost:3001"
read_only = true
#+end_src

验收：

- Web 显示 source namespace；
- 本地和远程文档身份不会混淆；
- 可以按 Source 浏览、读取和搜索；
- 远程不可用时显示 =Unavailable= 及原因，不伪装为空 Source；
- 远程文档显示只读能力；
- 远程引用保留稳定的 Source 与 locator；
- 默认查询只访问当前实例直接挂载的 Source，不递归执行上游的上游；
- 递归 Source 属于后续显式能力，必须有深度、循环和超时限制。

* 3. 核心信息模型

第一版不继续扩张 =Resource= 的职责。对外稳定模型收敛为以下概念：

** 3.1 Source

=Source= 是一个可访问的文档来源，不等于本地目录，也不等于数据库。

#+begin_src text
Source
├── source_id       当前实例内稳定标识
├── kind            markdown / org / notez-rest / ...
├── display_name
├── locator         根目录、URL 或外部端点
├── capabilities
└── auth reference
#+end_src

=source_id= 只在当前 Notez 实例配置范围内稳定。远程来源返回的外部身份必须另行保留，不能由 UI 或扫描器失败路径重新铸造身份。

** 3.2 Document

=Document= 是跨 Source 的统一读取模型：

#+begin_src text
Document
├── document_key       (source_id, source_local_id)
├── source_id
├── source_local_id    文件相对路径、远程 page id 等
├── title
├── format             markdown / org / remote...
├── content            原文或规范化正文
├── properties
├── objects
├── relations
├── revision
├── editability
└── raw_locator
#+end_src

第一版使用：

#+begin_src text
DocumentKey = (SourceId, SourceLocalId)
#+end_src

不要把路径、URL 或每次扫描新生成的 ULID 直接当作全局身份。文件移动后的身份追踪在第一版可以采用保守语义：移动视为旧文档删除和新文档创建；后续再加入基于内容或文件历史的连续性识别。

** 3.3 Object 与 Relation

解析出的标题、任务、标签、代码块和链接是 Document 的派生对象：

#+begin_src text
Document
  ├── Object
  │     ├── heading
  │     ├── task
  │     ├── tag
  │     ├── code-block
  │     └── link occurrence
  └── Relation
#+end_src

对象必须包含可回写的 =TextSpan= 或等价定位信息。没有定位信息的对象可以查询和展示，但不得直接用于结构化编辑。

** 3.4 Revision

=revision= 至少同时表达：

- Source 版本：本地文件内容 hash、远程 API revision 或 ETag；
- Notez 读取时观察到的版本；
- 写入时的 expected revision。

更新请求必须携带 expected revision。版本不匹配时拒绝写入并返回结构化冲突，不允许无条件覆盖。

* 4. Source 与能力协议

** 4.1 能力拆分

禁止使用单一 =can_write= 掩盖行为差异。第一版能力至少包括：

#+begin_src text
ListDocuments
ReadDocument
ReadRaw
SearchDocuments
ReadObjects
ReadRelations
CreateDocument
UpdateDocument
PatchDocument
DeleteDocument
WatchChanges
PollChanges
ExecuteQuery
ExecuteJanet
#+end_src

每个 Source 返回能力描述和限制，例如最大文档大小、是否支持 cursor、是否支持局部补丁、是否只读、是否可能产生有损写回。

** 4.2 端口

领域侧只定义端口：

#+begin_src rust
trait SourceReader {
    fn list(&self, request: ListRequest) -> Result<ListResponse>;
    fn read(&self, request: ReadRequest) -> Result<DocumentSnapshot>;
    fn search(&self, request: SearchRequest) -> Result<SearchResponse>;
}

trait SourceWriter {
    fn apply(&self, request: ApplyDocumentChange) -> Result<AppliedChange>;
}

trait ChangeObserver {
    fn poll(&self, cursor: Option<Cursor>) -> Result<ChangeBatch>;
}
#+end_src

实际代码可使用异步 trait 或现有项目惯用接口；这里的重点是读、写、观察分离，并且没有默认空实现。一个 Source 不支持某项能力时必须返回 =UnsupportedCapability=。

** 4.3 第一批 Adapter

| Adapter | 第一版能力 | 写入策略 |
|---------+------------+----------|
| Local Markdown | list/read/search/objects/relations/watch/patch | 支持文本补丁 |
| Local Org | list/read/search/objects/relations/watch | 支持受限字段补丁；无法安全写回则拒绝 |
| Remote Notez REST | list/read/search/objects/relations/capabilities | 只读 |
| Notion | 不进入第一版实现 | 后续只读优先 |
| Anytype | 不进入第一版实现 | 后续只读优先 |

* 5. 编辑与写回

** 5.1 统一写入管道

所有写操作必须经过：

#+begin_src text
Web / CLI / MCP / Janet command
              |
              v
       UpdateDocumentRequest
              |
              v
          Dispatcher
              |
              ├── capability check
              ├── authorization
              ├── expected revision check
              ├── document / span validation
              ├── Change creation
              ├── source writer
              ├── projection refresh
              └── audit record
#+end_src

Janet 只能生成标准的 =UpdateDocumentRequest= 或调用受限的只读 API；不能拿到 =SourceWriter=、文件路径或数据库连接。

** 5.2 两种编辑模式

第一版同时支持两种明确模式：

*** 原文编辑

用户编辑完整 Markdown / Org 文本，服务端以 expected revision 检查后写入。为降低覆盖风险，必须：

- 检查源 revision；
- 记录旧版本和新版本 hash；
- 写入失败时保留用户草稿；
- 不在 revision 不匹配时自动覆盖；
- 写入后重新解析文档并更新投影。

*** 结构化编辑

用户修改标题、任务状态、属性或标签等对象字段。引擎把修改转换为 =TextPatch=：

#+begin_src text
TextPatch
├── span: start..end
├── replacement
├── expected fragment hash
└── semantic operation
#+end_src

应用补丁前同时检查文档 revision 和 expected fragment hash。补丁无法安全应用时返回冲突，不回退到整文覆盖。

** 5.3 Markdown 写回

第一版 Markdown 支持：

- 正文原文编辑；
- 标题和任务的结构化补丁；
- Frontmatter 中已识别字段的受限补丁；
- 标签和链接的显式编辑。

未知 Markdown 扩展必须保留原文。解析器无法提供稳定 span 时，只允许原文编辑，禁止结构化写回。

** 5.4 Org 写回

第一版 Org 只承诺下列结构化写回：

- headline title；
- TODO keyword；
- priority；
- property drawer 中已识别属性；
- planning 中的日期字段。

以下情况必须拒绝结构化写回并给出原因：

- 目标 span 不明确；
- 同一字段存在多个候选位置；
- 文档包含无法安全保留的未解析结构；
- expected revision 已变化；
- Source 不支持该操作。

拒绝安全写回优于静默破坏 Org 文件。

** 5.5 Change 与 Journal

第一版不要求完整分布式事件溯源，但所有成功写入至少生成：

#+begin_src text
Change
├── change_id
├── actor
├── source_id
├── document_key
├── operation
├── expected_revision
├── previous_revision
├── resulting_revision
├── patch or content reference
├── timestamp
└── trace_id
#+end_src

Change Journal 用于：

- 审计；
- 写入失败和冲突可见性；
- 投影刷新；
- 后续同步和离线队列的基础。

* 6. 查询模型

** 6.1 先稳定结构化查询

第一版查询协议使用可序列化的 Selector，而不是先实现完整 SLIQ：

#+begin_src text
Selector
├── And / Or / Not
├── Source
├── Format
├── TitleContains
├── TextContains
├── Tag
├── Kind
├── HasRelation
├── UpdatedAfter / UpdatedBefore
├── OrderBy
├── Limit
└── Cursor
#+end_src

同一 Selector 可被 CLI、HTTP、MCP、Web 和 Janet 调用。它是协议数据，不是某一种表面语法。

** 6.2 Janet 查询 API

Janet 暴露的第一版 API 应该是稳定的小集合：

#+begin_src janet
(notez/sources)
(notez/search {:text "design" :source "local" :limit 20})
(notez/read document-key)
(notez/objects document-key)
(notez/relations document-key)
(notez/render-list rows)
#+end_src

这些函数返回普通 Janet 数据结构，但底层请求仍由 Engine 执行。Janet 不直接访问 ProjectionStore 或 Source Adapter。

** 6.3 查询执行边界

本地 Source 可以下推查询；远程 Source 可以只支持查询子集。Engine 必须明确报告：

- 实际覆盖的 Source；
- 是否部分结果；
- 哪些条件由上游执行；
- 哪些条件在本地执行；
- 上游不可用或不支持的条件；
- 分页 cursor 的来源。

跨 Source 查询第一版采用“每个直接 Source 查询，再在当前实例合并”的语义；不递归查询上游的上游。

* 7. Janet 运行时设计

** 7.1 执行位置

第一版 Janet 只在 Notez Engine 所在的 native 服务端执行。Web、CLI 和 MCP 都通过 Protocol 请求 Janet 执行，不在浏览器中各自嵌入运行时。

原因：

- 统一权限和资源限制；
- 避免 WASM、桌面和移动端出现多套 Janet 运行时；
- 避免远程 Source 凭据进入客户端；
- 保证 CLI、Web、MCP 语义一致。

** 7.2 沙箱能力

默认 Janet 环境只包含：

- 基础数据结构和纯函数；
- 显式注入的 Notez 查询 API；
- 受限字符串、数组、字典和格式化函数；
- 结构化渲染构造器。

默认不包含：

- 任意文件系统 API；
- 网络 API；
- 进程和 shell API；
- 环境变量和系统凭据；
- 数据库连接；
- 任意 Rust callback；
- 直接写入 Source。

脚本请求必须有：

#+begin_src text
JanetExecutionContext
├── actor
├── source scope
├── document scope
├── input revision
├── timeout
├── memory / result limit
└── trace id
#+end_src

** 7.3 Janet 输入与输出

脚本输入必须显式传入。禁止隐式暴露全局 workspace：

#+begin_src janet
(def rows (notez/search {:tag "project" :limit 10}))
(notez/render-list rows)
#+end_src

脚本输出只允许以下类别：

- scalar；
- JSON-compatible map / array；
- Markdown fragment；
- structured view；
- structured error。

HTML 不作为默认脚本输出。若 Web 需要 HTML，必须经过统一 sanitizer 或结构化渲染树出口。

** 7.4 Janet 错误

错误必须区分：

- syntax error；
- runtime error；
- timeout；
- result too large；
- unsupported API；
- source unavailable；
- permission denied；
- stale revision；
- renderer error。

错误结果进入文档局部 widget 或查询响应，不应让整个 Web 请求只返回 =Internal=。

** 7.5 脚本版本与缓存

脚本执行结果缓存键至少包含：

#+begin_src text
(script hash, input revision set, query parameters, runtime version)
#+end_src

脚本、模板和运行时版本变化时缓存失效。第一版可以不持久化脚本结果，但必须保留可计算的失效条件。

* 8. 统一 Protocol 与表面层

第一版 Protocol 只实现真实闭环所需的请求：

#+begin_src text
ListSources
GetSourceCapabilities
ListDocuments
ReadDocument
SearchDocuments
UpdateDocument
ExecuteJanet
WatchSource
#+end_src

Rust 表示保持强类型：

#+begin_src rust
enum Request {
    ListSources(ListSourcesRequest),
    GetSourceCapabilities(GetSourceCapabilitiesRequest),
    ListDocuments(ListDocumentsRequest),
    ReadDocument(ReadDocumentRequest),
    SearchDocuments(SearchDocumentsRequest),
    UpdateDocument(UpdateDocumentRequest),
    ExecuteJanet(ExecuteJanetRequest),
    WatchSource(WatchSourceRequest),
}
#+end_src

避免使用万能 =Value= payload。MCP schema、HTTP JSON、CLI 参数和 Web 请求都从这些 DTO 翻译或生成。

表面层禁止：

- 直接访问 SQLite；
- 直接读取或写入 Source；
- 自己实现过滤、revision 检查和能力判断；
- 把领域错误压缩成无上下文字符串；
- 为远程对象生成本地伪身份。

* 9. 运行时与模块重构

目标不是一次性把所有代码拆成大量 crate，而是先明确依赖方向：

#+begin_src text
notez-domain
    |
notez-protocol
    |
notez-engine  <── ports: SourceReader / SourceWriter / ProjectionReader / Journal
    |
    +── notez-fs / notez-format-markdown / notez-format-org
    +── notez-sqlite
    +── notez-janet
    +── notez-composition
           |
       CLI / MCP / HTTP / Web
#+end_src

** 9.1 Domain

纯领域类型和算法：

- SourceId、DocumentKey、ObjectId、Revision；
- Document、Object、Relation、TextSpan、TextPatch；
- Selector；
- Change、Conflict、Capability；
- 错误语义中与基础设施无关的部分。

Domain 不依赖 rusqlite、文件系统、Janet、HTTP 或 Dioxus。

** 9.2 Protocol

所有表面共用的 Request、Response、Error 和 JSON Schema。Protocol 不包含具体存储实现。

** 9.3 Engine

负责：

- Dispatcher；
- Source 注册与能力查询；
- 查询编排；
- 写入校验；
- revision 检查；
- Change / Journal；
- Janet 执行上下文；
- 投影失效和刷新通知。

Engine 不直接构造具体文件系统或数据库对象，通过组合根注入端口。

** 9.4 Format Adapter

Markdown 和 Org parser / writer 负责：

- 解析；
- LinkOccurrence；
- Object 和 Relation 提取；
- TextSpan；
- TextPatch 应用；
- 格式能力和有损风险报告。

解析器不得自己通过全局路径读取文件；Source Transport 负责 I/O。

** 9.5 Janet Adapter

Janet Adapter 只负责：

- 初始化受限 VM；
- 注入 Engine 提供的白名单 API；
- 设置 timeout / memory / result 限制；
- 转换 Janet 值和 Protocol 值；
- 结构化错误和 trace。

它不能成为绕过 Engine 的第二个应用层。

** 9.6 Composition Root

唯一组合根负责装配：

- 配置；
- Source Registry；
- Format Registry；
- Projection；
- Journal；
- Janet Runtime；
- HTTP / MCP / CLI surfaces。

Web、CLI 和 MCP 必须从同一个组合根获得 Engine，不能各自 new 一个简化版 ApplicationFacade。

* 10. Web 交互模型

第一版 Web 不是资源诊断后台，而是文档工作区：

#+begin_src text
左栏       中栏                 右栏
Source     文档列表 / 编辑器     属性 / 链接 / 执行状态

第一版页面优先级：

1. Source 选择；
2. 文档列表和搜索；
3. 文档阅读；
4. 原文编辑；
5. 结构化字段编辑；
6. Janet 动态块；
7. revision / 冲突提示；
8. 关系和附件预览。

交互必须使用明确的单向状态流：

#+begin_src text
User Action
  -> Protocol Request
  -> Engine
  -> Protocol Response
  -> Client Store
  -> View
#+end_src

在 hydration 不稳定期间，编辑和搜索必须仍有明确可用的 HTTP / HTML fallback；但 fallback 和 WASM 不能分别实现业务语义。两者都调用同一个 HTTP Protocol。

* 11. 迁移阶段

每个阶段都必须保持已完成能力可运行，不建立长期双轨实现。

** R0：可用性卫生

- 明确当前组合根；
- 修复 Web、CLI、MCP 的运行时装配差异；
- 删除 UI 伪造身份和静默空实现；
- 让 Source capability 与实际行为一致；
- 把现有测试和 acceptance 脚本中的错误断言修正；
- 固定一个本地 Markdown 浏览、搜索、编辑 smoke path。

验收：本地 Markdown 能通过 Web、CLI、MCP 读取，且三者使用同一服务实例和同一结果语义。

** R1：Document / Source / Protocol 收口

- 收敛 SourceId、DocumentKey、Revision；
- 增加 Source capability DTO；
- 实现第一批强类型 Request / Response；
- CLI、MCP、Web 迁移到 Dispatcher；
- 删除表面直接依赖 SQLite / 文件的路径。

验收：ListSources、ReadDocument、SearchDocuments 在三种表面结果等价。

** R2：Markdown 编辑闭环

- 实现原文编辑；
- 实现 expected revision；
- 实现 Markdown TextPatch；
- 写入后重新解析和刷新投影；
- 记录 Change 与 Audit；
- 外部文件变化触发刷新。

验收：Web 编辑内容实际写入文件；并发修改不静默覆盖；外部编辑可被重新读取。

** R3：Org 受限编辑

- 保留 Org 原始文本和 span；
- 支持 headline / TODO / property / planning 的受限补丁；
- 为无法安全写回的情况返回明确错误；
- 扩展 golden 保真测试。

验收：支持字段的修改不会破坏未识别内容；不支持的修改被拒绝而不是整文件覆盖。

** R4：Janet 查询与渲染

- 选择并验证 Janet embedding 方案；
- 新建 notez-janet adapter；
- 实现受限 VM 和执行上下文；
- 暴露 search/read/objects/relations/render API；
- 支持文档内 Janet block；
- 接入超时、结果大小、错误和 trace；
- 禁止任意 I/O 和直接写入。

验收：同一 Janet 查询可以从 Web、CLI、MCP 执行；异常只影响局部结果；超时可控；脚本不能绕过权限和 revision 检查。

** R5：Remote Notez Source

- 冻结最小 REST 协议；
- 实现 capability discovery；
- 实现 list/read/search；
- 实现 source namespace 和稳定远程 locator；
- 实现上游错误和部分结果状态；
- 默认只读；
- 禁止递归执行上游 Source。

验收：一个 Notez 实例可读取另一个实例的文档，并在不可用、无权限和能力不支持时显示可区分状态。

** R6：可靠写入与后续扩展

- 完善 journal 查询、重试和冲突投影；
- 引入离线 Change 队列；
- 设计 Remote Notez 写入协议；
- Notion / Anytype 只读 Adapter；
- Janet 受控命令和写入 proposal；
- Desktop / Mobile 复用 Protocol。

这些内容不得倒灌回 R0-R4，除非第一版验收发现其为编辑闭环的必要条件。

* 12. 测试与验收策略

** 12.1 格式保真

每个写回操作至少验证：

- 未修改区域字节或规范化等价；
- 目标 span 修改正确；
- 未识别语法仍存在；
- revision 不匹配被拒绝；
- patch 失败不产生部分写入；
- 重复应用同一 patch 不产生意外重复。

** 12.2 跨表面一致性

对相同 fixture，分别通过 CLI、HTTP、MCP 和 Web 后端执行：

- list sources；
- read document；
- search；
- update；
- execute Janet。

验证领域响应、错误分类、revision 变化和审计记录一致。呈现格式可以不同，领域结果不能不同。

** 12.3 Janet 安全性

至少验证：

- 访问未注入的文件路径失败；
- 网络访问失败；
- 进程启动失败；
- 超时被终止；
- 超大返回被拒绝；
- Source 权限不足时查询失败；
- Janet 不能直接更新文档；
- Janet 生成的 UpdateRequest 仍经过 revision 和 capability 检查。

** 12.4 真实 smoke test

不能只运行单元测试。发布前必须运行真实场景：

#+begin_src text
临时 workspace
  -> 启动 Notez 服务
  -> Web 打开文档
  -> Web 编辑并保存
  -> 外部进程修改文件
  -> watch / reload
  -> CLI 搜索
  -> MCP 读取
  -> Janet 查询和渲染
  -> 检查原始文件、revision、journal
#+end_src

* 13. 风险与应对

** 13.1 Janet 依赖和平台支持

风险：Janet embedding 在 Linux、Windows、macOS 和未来客户端上的构建方式不同。

应对：第一版明确 Janet 只在 native Engine 服务端执行；先做独立 embedding spike，确认构建、生命周期、超时和错误转换，再进入核心迁移。客户端不直接依赖 Janet。

** 13.2 Org 写回破坏内容

风险：解析对象比原文简单，结构化写回会覆盖未知语法。

应对：span 补丁、fragment hash、能力声明和拒绝安全写回。不得使用“解析后重新序列化整个文档”作为默认方案。

** 13.3 统一模型变成最低共同能力

风险：为了兼容 Notion / Anytype / Org，把所有内容压扁为 title + body。

应对：统一模型只表达稳定交集；保留 raw representation、Source capability 和 fidelity metadata；来源专有能力不成为 Core 必选字段。

** 13.4 多个运行时继续分裂

风险：Web、CLI、MCP 各自构造 Engine，表面上协议统一，实际行为仍不同。

应对：组合根唯一装配；表面层只翻译 Protocol；增加跨表面等价 acceptance 测试。

** 13.5 动态内容执行成本失控

风险：Janet 查询触发大量 Source 访问，阻塞 Web 请求或放大远程调用。

应对：执行预算、查询 limit、结果 limit、超时、Source 访问计数、缓存和 trace；第一版禁止隐式全库扫描。

* 14. 完成定义

第一版重构只有在以下条件全部满足时才算完成：

- 本地 Markdown 可通过 Web 编辑并可靠写回；
- 本地 Org 可阅读、搜索，并支持文档声明的受限结构化编辑；
- revision 不匹配不会静默覆盖；
- 未识别格式不会因结构化编辑被静默删除；
- CLI、Web、MCP 经过同一个 Protocol 和 Engine；
- Janet 可以查询和渲染显式数据；
- Janet 受 timeout、result limit 和权限约束；
- Janet 无法直接访问文件系统、网络、进程或写端口；
- Janet 错误不会让整个页面退化为无上下文 Internal；
- Change 和 audit 能指出 actor、source、document、revision 和结果；
- Remote Notez Source 可以只读挂载并报告能力、不可用和权限状态；
- 投影删除后可以从本地原始文件重建；
- 真实 Web、CLI、MCP、Janet smoke test 通过；
- 新增 Source 不需要修改既有表面的领域语义。

* 15. 后续需冻结的公开契约

实现开始前需要冻结以下最小协议，而不是继续扩展愿景：

1. =SourceDescriptor= 与 capability 枚举；
2. =DocumentKey=、=Revision=、=TextSpan=、=TextPatch=；
3. =ReadDocumentRequest=、=SearchDocumentsRequest=、=UpdateDocumentRequest=；
4. =ExecuteJanetRequest= 与结构化执行结果；
5. 错误码：NotFound、Unavailable、Unauthorized、UnsupportedCapability、StaleRevision、InvalidPatch、ScriptError、ScriptTimeout；
6. Remote Notez 的只读 REST 资源和分页协议；
7. 文档内 Janet block 的最小语法与输出类型；
8. Change / Audit 的最小字段。

这些契约稳定后，才进行大规模 crate 拆分和 Web UI 重构。实现顺序必须由第一版验收路径驱动，而不是由最终架构图驱动。
