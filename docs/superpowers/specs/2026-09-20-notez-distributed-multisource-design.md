# Notez 多源、分布式与跨平台架构设计

> 状态：完成本轮设计自审，待用户审阅；不是实现完成声明，也不授权启动代码迁移。
> 日期：2026-09-20。
> 范围：Notez 目标架构、conex 适配边界、上游需求与分阶段验收。
> 证据：依据两仓库当前工作树静态检查；本轮未运行服务、跨设备同步、攻击复现或平台构建。已有未提交修改保留。旧验证记录不能代替当前端到端验收。

## 1. 结论与文档关系

**采用“Notez 管笔记语义，conex 管互联，可选复制模块管副本”的组合架构。** 本地读写不依赖 conex 服务在线；多源访问不以分布式同步完成为前提。

目标产品是本地优先的跨平台笔记工具：用户可以注册多个本地或远程 Source，将它们挂入 Space，统一阅读、编辑、搜索、引用；对于明确加入复制的自有数据，可跨设备离线编辑、交换历史并处理冲突。

本设计承接 [个人知识工作台重设计](2026-09-09-personal-knowledge-workspace-redesign.md) 的 Object—Projection—View、Space→Source→ObjectTree、目录对象及 `index.org` 正文绑定、文本源编辑和附件预览。它不重新设计 UI，也不把旧规格首期范围扩成一次性大重写。

文档职责：

- 旧工作台规格：产品交互、本地编辑和展示块。
- 本文：多源身份、互联/复制边界、写入恢复、跨平台能力与 conex 需求。
- [当前架构评审](../../current-architecture-and-redesign.md)：历史实现观察；其中阶段勾选和旧缺陷以代码为准。
- [conex 设计 v6](../../../../conex/docs/design/2026-09-14-conex-design.md)：conex 的规范候选；本文不能单方面更改其 wire、密码套件或交付状态。

本文如获批准，在交叉主题上优先于既有文档或代码注释中的旧口径：Journal 不全部可重建，Change append 不代表源写入成功，Space 与 Source 不合并为一个概念。当前公共执行入口仍是 `Request → ApplicationDispatcher → Response`；不以文档名义引入第三套协议。

## 2. 设计审核：保留与修正

| 审查项 / 候选方案 | 审核结论 | 本文决定 |
|---|---|---|
| conex 作为互联层 | 保留 | 先接只读数据连接，再按需求接写入、反连和复制 |
| 所有 Source 使用统一同步模型 | 修正 | 外部系统是独立权威；访问、缓存、导入和副本复制分别声明 |
| endpoint ID 直接作为 Source 身份 | 修正 | endpoint 是可变路由；稳定 Source 身份不能随 host 迁移改变 |
| 使用 CID 加 locator 派生长期对象身份 | 否决 | CID 标识内容版本；对象身份必须独立于正文和位置 |
| ObjectAddress 同时必带 Space、Source、native ID、Object ID | 简化 | 对象地址只有稳定 Source ID 与源内对象键；Space 是访问/展示上下文 |
| 所有 Change 都加 DAG 和签名 | 修正 | 本地操作记录不等于复制历史；仅复制的变更消费 conex 同步契约 |
| Journal 与 SQLite 都可丢弃重建 | 否决 | 索引可重建；未发送操作、身份映射、密钥、复制历史不能当缓存丢弃 |
| 文件 hash 检查加 rename 等于 CAS | 否决 | rename 解决替换完整性，不提供跨任意写入者的条件更新 |
| 增加十余个 can_* 布尔值 | 简化 | 方法能力加版本/恢复等语义约束；能力、授权和在线状态分开 |
| 先创建六个 Conex*Mapper/Adapter 类 | 否决 | 从一个边界适配模块开始；只在出现独立生命周期时拆分 |
| 强制所有 UI 使用同一个渲染运行时 | 否决 | 共享用例、地址和错误语义；允许 SSR、嵌入式、远程客户端各自呈现 |

### 2.1 三种路线比较

| 路线 | 优点 | 代价 | 决定 |
|---|---|---|---|
| Notez 自建互联、复制和发现 | 无上游交付依赖 | 重复实现会话、安全、传输和 DAG | 不选 |
| Notez 全部改成 conex Object 应用 | 底层模型看似统一 | 外部 Source 和本地文件被迫改造；当前 conex 尚不具备完整复制能力 | 不选 |
| Notez 领域独立，conex 边界接入，复制按 Source 启用 | 可先交付多源；本地与远程职责清晰 | 必须维护并验证两侧映射契约 | 推荐 |

## 3. 三种不同的“分布式”

| 模式 | 事实与写入权威 | 网络中断时 | 示例 |
|---|---|---|---|
| 远程使用 | 远程 Notez host | 已缓存内容可读；不冒充本地提交成功 | 手机连接家中 Notez |
| 多源联邦 | 每个 Source 各自权威 | 单源失败不隐藏其他源的成功结果 | 本地笔记、远程 Notez、Anytype 同时搜索 |
| 多副本复制 | 显式加入复制的数据集及其因果历史 | 成员设备可本地提交，恢复连接后可能冲突 | 笔记本和台式机离线修改同一笔记 |

三个模式可共存，但不能互相冒充。HTTP 访问不等于同步；WSS 恢复不等于数据收敛；拥有 CID 不等于拥有读取权限或完整副本。

首个互联切片只交付联邦只读访问。完整目标仍包含多副本离线编辑，安排在复制契约和故障验收完成之后；不是删除这一目标。

非目标：首版字符级多人实时协作、任意第三方系统双向镜像、跨 Source 分布式事务、自动语义冲突消解、多 host 无损会话漂移。ACP 网关不是笔记互联的前置条件。

## 4. 领域、身份与事实归属

### 4.1 核心概念

| 概念 | 定义与不变量 |
|---|---|
| Space | 对象引用、Source 挂载、视图和访问策略的工作容器；不是文件根目录 |
| Source | 一个有稳定身份的事实集合，例如一个笔记库或上游 workspace；不是适配器类型 |
| SourceAdapter | 已安装的访问实现，同一种实现可以创建多个 Source 实例 |
| Object | Source 内稳定对象，独立于名称、路径、当前内容和所在 View |
| Projection | 从事实解析或索引得到的可重建读模型 |
| Locator | 当前 Source 内位置，可变；不能用于跨设备长期标识 |
| Revision | 来源提供的不透明版本，必须按原来源语义比较 |
| Content CID | 特定编码规则下不可变内容地址，不代表对象身份或业务 revision |
| Operation ID | 一次可恢复业务意图的去重标识，不是 revision，也不是网络 request ID |
| Change CID / heads | 复制历史的变更及因果前沿；只在启用复制时存在 |

目标地址的概念形状（不是当前 wire 声明）：

```text
ObjectAddress = { sourceId, objectKey }
SourceRoute   = { sourceId, endpointId, remoteScope, credentialRef }
RequestScope  = { spaceId, selectedSources, authenticatedPrincipal }
```

- Source ID 在首次登记权威数据集时生成或绑定上游稳定身份；显示别名、服务器 URL、endpoint ID 不参与身份生成。
- 一个 Source 被两个 Space 引用，地址不变；两个独立 Source 即使文件同名同内容，也不自动合并身份。
- endpoint 可迁移；只有验证数据集身份与授权后才能更新 SourceRoute，不能依据目录返回的新地址自动认领原 Source。
- tenant/issuer 属于身份和授权上下文；需要时隔离注册表，不把可变租户路由混入每个 Object ID。
- 当前 `ResourceRef` 可继续作为内部投影键；公共边界必须具备无歧义的 Source 上下文，不要求批量重写所有 ULID。

### 4.2 本地文件的稳定身份

优先采用已经存在且有效的原生 ID。无原生 ID 的文档和目录首次登记生成持久对象键，保存于 Source 的可备份身份目录；不得将该目录放入可随时清空的索引缓存。

- Notez 内部 rename/move 保持对象键；“复制为新笔记”生成新对象键。
- 原生 ID 重复导入时报告冲突，不静默覆盖。
- 外部编辑器改变正文不改变文档对象键。
- 外部工具移动无 ID 文件，只在证据唯一时重新绑定；存在多个候选则保留未解析状态，由用户确认，不能声称任意外部移动都可自动识别。
- 未分配持久 ID 的 heading/block 只提供版本绑定的位置引用；不得宣传为移动不变的稳定块引用。
- 导出正文仍是普通 Org/Markdown/TXT。仅导出正文保留可读性，但不承诺保留没有嵌入正文的身份、历史和视图数据。

### 4.3 目录与跨平台文件名

目录是独立对象，`index.org` 作为其正文投影，不额外创建第二个文档对象。同一路径争用是命名冲突，不是同一对象。

逻辑 locator 与本机路径映射分离。跨平台物化必须处理大小写碰撞、Unicode 形式、Windows 保留名、路径长度及符号链接。不能表示的文件保留完整对象和原始名称，标记 `materialization_conflict`；不静默改名或覆盖其他文件。

### 4.4 数据耐久性分类

| 数据 | 可从什么重建 | 删除/备份规则 |
|---|---|---|
| 正文和附件 | 有完整备份或已验证副本时恢复 | Source 事实，不是缓存 |
| 对象键、Space 分类/引用、Source 注册 | 原生 ID 或独立配置/元数据备份 | 无其他事实副本时不可删除 |
| 搜索、解析树、反向链接索引 | 原文、稳定身份和解析器版本 | 可重建 |
| 操作日志、未发送 outbox、应用游标 | 不能只靠当前正文重建 | 必须耐久保存，完成保留条件后才清理 |
| 复制历史、密钥、ACL、被 pin 的 blob | 完整且获授权的副本/备份 | 独立保留与恢复策略；密钥不能替代数据备份 |
| 诊断/审计日志 | 通常不能重建历史事实 | 按保留策略归档；不冒充同步流 |

## 5. Source 注册与联邦读取

### 5.1 三张表的职责

1. **工厂注册表**：装配根登记已安装 Adapter；远端清单不得加载可执行代码。重复 kind 默认拒绝，替换必须显式配置。
2. **Source 目录**：保存稳定 Source ID、显示名、类型、路由/本地根、凭据引用和模式。
3. **Space 挂载**：将已有 Source 或其子范围加入 Space，保存视图规则和授权范围。

配置统一归 `notez.toml` 及本机安装配置管理；旧 `.notez/sources.json` 只作为一次性迁移输入。迁移遇到同 ID 不同内容应失败并报告，不保留两份长期可写配置。机器绝对路径和 secret 不复制到其他设备；复制的挂载仅携带逻辑 Source 引用，各设备自行绑定位置和凭据。

控制面操作进入现有协议：列举/登记/修改/卸载 Source、挂载/卸载到 Space。更新配置比较配置 revision；卸载挂载不删除正文，注销与数据删除是不同动作。只列出调用者获授权的 Source，不泄露未授权名称、路径和错误详情。

### 5.2 能力、权限、状态相互独立

能力用支持的方法及约束描述，例如读/列举/搜索/写/删除/观察，以及：

- 版本语义：无可靠版本、内容版本或支持原子条件写的来源版本；
- 观察语义：无观察、仅失效通知、可恢复游标；
- 操作恢复：只读、上游幂等、可查询结果或不可安全重试；
- 内容限制：MIME、最大尺寸、分页与 blob 支持。

这是目标语义，不要求立即新增一套通用插件 DSL。一个方法的可用性取决于“实现支持 ∩ 当前授权 ∩ 当前状态”；只读上游不会因本地配置 `read_only=false` 获得写能力。

### 5.3 导入、缓存与查询

- 无变更游标的 Source 可以使用显式刷新和有界全量分页；不因此禁止接入。
- 全量扫描只有在所有页完成且快照语义成立时，才可依据“未出现”删除旧投影；超时、分页失效和权限变化不能当成远端删除。
- 可恢复观察必须带 Source/范围绑定的 cursor；过期返回“需重新同步”，不能从头静默跳过缺口。
- 搜索返回成功项目和逐源状态：成功空结果、不可达、权限拒绝、部分结果、缓存陈旧必须可区分。
- 一个慢源不能耗尽其他源全部预算；有界并发与独立 deadline，不持有整个 Engine 锁跨远程网络等待。
- 缓存按主体授权范围、Source、对象、版本及解析器版本隔离；不能先读全量敏感数据再做 UI 过滤。
- 默认不自动遍历远程 Notez 的远程挂载。只导出显式批准的 Source；避免 A 引用 B、B 引用 A 形成扫描环或放大权限。
- 将外部 Source 内容“复制到个人笔记”是创建新对象并记录来源关系，不是悄悄加入双向镜像。

## 6. Notez 与 conex 的边界

### 6.1 责任划分

| 层 | Notez 负责 | conex 负责 |
|---|---|---|
| 产品 | Space、Source 挂载、目录/笔记对象、编辑、预览、关系和检索 | 不包含笔记 UI 或 Org/Markdown 领域模型 |
| 调用 | typed Request/Response、笔记用例、来源版本语义 | 方法路由、认证身份映射、策略执行、连接及失败语义 |
| 内容 | MIME 解析、文档物化、附件引用 | CID/分块/上传/下载及声明的持久性 |
| 复制 | 笔记状态到复制对象的投影、冲突 UI、文件物化 | 可选复制模块的签名 DAG、heads、ACL、密钥 epoch、复制与发现 |

不能将“conex 内容模块有 commit”解释为“Notez 笔记已经提交”。blob commit、业务操作完成和复制收敛分别确认。

本地 Adapter 仍直接访问本地事实，不为统一形式强制经 HTTP 或运行独立 conex 进程。只读连接不强制创建长寿命 Session。适配代码从一个模块起步，不预建 Mapper 类族或未使用的新 crate。

### 6.2 两个方向分别交付

**Notez 消费 conex Source：**

```text
客户端 → Notez Request/Dispatcher → 已授权 Source
      → ConexSourceAdapter → conex source/list/read/search
      → text + MIME + resource ID + version/CID
      → Notez parser → projection → 客户端
```

**将 Notez 导出给 conex：**

```text
conex consumer → 已安装 Notez provider
               → 验证身份委托和导出 Source 范围
               → Notez 公开协议 → Notez Runtime
```

第二个方向不是首个只读消费切片的前置条件。Notez provider 不直接读 Notez SQLite，不绕过 Dispatcher，也不把任意内部 Request 暴露为无约束万能调用。

现有 `ReadResource` 返回资源元数据，不能假定它就是远程原文 API。导出契约必须有经授权的原文/附件读取及稳定来源 ID；缺少的操作先在 Notez 协议补齐。

### 6.3 映射规则

| 边界项 | 规则 |
|---|---|
| endpoint / provider | endpoint 定位路由；provider 表示提供方；均不直接替代稳定 Source ID |
| resource ID | 不透明的源内资源键；fs 实现若使用路径，只能承诺位置身份，不能假装 rename-stable |
| revision | 原样携带上游 token；本地内容 hash 另存；不能从 CID 猜测 ETag |
| CID | 按 conex 内容格式验证；Notez 原始 SHA-256 字符串不是 CID 的同义写法 |
| errors | 保留拒绝、无资源、版本冲突、超时、不可达、未知结果和缺失内容的区别 |
| principal | 从受信任连接/授权委托取得；请求体自报 actor 不构成身份 |
| schema | Notez Rust DTO 和 conex proto 各自是本边界唯一类型源；适配器消费生成类型/校验器并验证映射 |

## 7. 写入、并发与崩溃恢复

### 7.1 协议决定

保留现有 `RevisionPrecondition::MustMatch` 与 `MustNotExist`。先补齐创建、注册和冲突裁决等绕过路径，不另起新一代执行 API。未接入执行入口的 Command/Query 候选类型不应作为可执行能力广告。

业务对象更新比较对象 revision，配置更新比较配置 revision，副本更新比较已观察 heads；查询、扫描观察和内容寻址上传不机械要求同一种 revision。用户明确选择覆盖时仍要携带其确认过的当前 revision；不得新增无条件 force 旁路。

### 7.2 本地原文写入

所有 Notez 写入者针对同一 Source 使用跨进程的排他写入协调；进程内 Runtime 缓存不替代跨进程锁。同一 Runtime 并发首次打开也必须得到同一个 Engine。

概念提交过程：

1. 验证身份、Source 范围、方法能力和 revision；获取该来源的写入协调。
2. 耐久记录操作意图、旧/新版本、内容引用与恢复标识；此时不是业务成功，也不发送复制 Change。
3. 重新核对源版本，按平台能力执行安全创建或替换；创建禁止覆盖已有目标。临时文件唯一，持久性实现包含必要的文件/目录刷盘，不仅是 rename。
4. 确认源写入结果后，在耐久事务中记最终操作结果及待导出的事件/outbox 引用；可重建索引随后更新。
5. 源已写入但索引失败时，返回“源已提交、索引待恢复”的结构化状态，不能报成可安全重试的普通失败。

文件系统与 SQLite 不是一个原子事务。崩溃恢复必须查询操作意图、写入证据及现有源版本；无法证明是否执行时保留 `outcome_unknown`，不盲目重放，也不只凭内容恰好相同宣称是本操作执行成功。

普通文件系统不能提供针对不遵守锁的任意外部编辑器的通用 CAS。此保证仅覆盖受协调的 Notez 写入者；外部变化用 watcher/重新读取发现并保留冲突版本。对这种来源不得向远端广告无条件的原子 CAS 保证；需要强保证时，由单写权威控制物化目录，或使用上游原生条件写接口。

### 7.3 远程写入与重试

- 上游支持原子条件更新，才传递并广告 `MustMatch` 类语义。
- 没有可靠原子条件写时保持只读；不能用“先 GET 再 PUT”伪造条件写。
- 同一 Operation ID 与参数摘要重复提交应返回原结果；同 ID 不同参数拒绝。
- 上游已执行而响应丢失时，有上游幂等键/状态查询才能安全恢复；仅有本地去重表不解决跨系统崩溃窗口。
- 自动重试仅针对确认可重试的操作。取消请求与业务回滚不是一回事。

本地操作日志、审计和复制 DAG 职责不同。可以复用存储事务和内容引用，但不能把扫描计数日志包装成可回放的复制历史。

## 8. 多副本复制设计

### 8.1 复制单元与 Space 映射

只有显式启用复制的自有 Source 才加入复制组。外部 Notez/Anytype Source 默认保持远端权威；缓存不自动成为可写副本。

建议首版一个可复制 Source 对应一个 conex Space（安全与历史容器）。Notez Space 是 UI/组织容器，两者不要求一一对应；一个 Notez Space 可挂载多个复制 Source 和多个外部 Source。共享分类/视图元数据需要复制时，保存为独立的元数据 Source，不把本机路径和凭据写入其中。

同一对象在不同权限复制组之间复制，视为显式导出/新副本绑定；不能只因 Object ID 或 CID 相同自动穿透 ACL。

### 8.2 笔记状态到复制对象

不在 Notez 再定义第二套签名算法、DAG 或密钥协议。conex 的 `object-mv-v1` 若通过发布门槛，则 Notez 为其定义版本化应用 payload：

- 稳定 object key 与对象种类；
- 正文/附件的内容 CID；
- 标题、父目录对象键、名称及需要共享的属性；
- 删除状态与内容格式版本。

首版把整篇正文作为一个版本化值，不实现字符级 CRDT。不同对象可独立合并；同一对象的并发正文版本均保留，由 Notez 展示并选择或编辑合并。合并算法产生的候选不能静默覆盖原版本；裁决创建引用所有被裁决 heads 的新变更。

目录移动/同名创建产生结构冲突时，物化器拒绝形成环、覆盖已有对象或写出根目录；副本仍保存完整历史，UI 呈现待处理冲突。

### 8.3 复制与物化分离

```text
本地写入/外部观察 → 耐久本地版本 → 待导出记录
                → conex 变更构造/签名与 outbox → 网络发送

网络接收 → 身份/ACL/签名/CID/父依赖验证 → 持久接收确认
        → 幂等应用 → 更新 heads/游标 → Notez 解析/文件物化
```

- 父依赖或内容缺块时暂存，不推进“已应用”游标。
- ACK 接收、耐久保存、领域应用和全体设备收敛不是同一状态；UI 分别显示。
- Notez 导出队列负责从本地已提交事实生成复制变更，保存 Operation→Change CID 关联；conex 队列负责同一变更的网络投递。恢复只能重投同一变更，不能重新创造并发历史。
- 接收游标只有在变更耐久保存并幂等应用后推进；投影可滞后但必须可重建并显示状态。
- 接收物化引发 watcher 事件时，通过来源标识/已物化版本识别，避免无限回传。
- 删除为 tombstone；删除与修改并发保留冲突，不能自动复活或自动丢弃修改。
- 未确认投递、缺失依赖和有效引用/pin 的数据不得 GC。长期离线设备超出保留窗口后明确要求重新取快照。

### 8.4 旧 folder sync 迁移

现有 manifest 不能证明完整因果历史；不得从旧 `parent_snapshots` 和合成 head 编造可信 DAG。

迁移流程：备份两端全部正文、冲突和旧对象库；停止旧同步写入；人工或工具识别未决版本；生成含所有保留分支的新基线；校验两端导入结果；启用新复制路径。成功前不删除旧副本。

旧 folder sync 不与新复制同时写同一 Source。未来共享文件夹可以成为同一复制契约的承载实现，但不是保留旧历史模型的理由，也不是首个互联切片必须完成的工作。

## 9. 安全与信任

1. Web 页面、raw/preview、HTTP API、MCP 的读取和写入均接入统一身份与资源授权；不能只保护 POST。
2. 浏览器使用受保护会话，原生/CLI 使用合适的 token；共享 Principal 和策略，不要求将 bearer secret 塞进 HTML 表单。Cookie 写操作校验 Origin/CSRF。
3. 公网 Source 选择只接受获授权的逻辑 ID；本地管理员 CLI 才允许显式路径导入。授权先于开库、扫描或远程请求。
4. Notez 与 conex 两端均校验本地策略，权限取交集。代理用服务身份时明确标为服务，不伪装成原用户；用户委托必须绑定受众、期限和 Source 范围。
5. 发现只返回候选；静态邀请、预置身份或信任链决定预期对端，目录签名不能自行授予访问权。
6. 同步 locator、object hash/CID 和归档条目均视为不可信输入；拒绝绝对路径、父目录逃逸、非法内容地址及符号链接逃逸。
7. broker 可读内容与 relay 密文平面分别授权。检索加密副本在授权设备上完成；服务端明文索引需要另行显式导出授权。
8. ACL 撤销不等于擦除已下载的明文。离线写可本地保存，但重新发布时可能因权限撤销被拒；保留本地分支而非丢弃。
9. 密钥管理、密码套件、签名规范字节、ACL cutoff 与恢复流程由 conex 专项契约负责；未完成安全评审前不广告端到端加密复制。
10. 跨不可信网络使用 TLS/WSS 并验证预期服务身份；仅显式本机开发配置可使用明文连接。登记远端地址是管理权限，重定向、DNS 变化和实际拨号地址均受出站策略约束；允许私网 provider 不等于允许任意 SSRF。
11. 远程原文、HTML 预览、附件和 Janet 块是非可信内容；保留 HTML 清洗与只读沙箱，不能因为来自已认证 Source 就允许文件、网络、进程或数据库访问。

## 10. 跨平台与运行时

| Surface | 首阶段 | 后续目标 | 约束 |
|---|---|---|---|
| Web | SSR Reader/Editor，远程 Source 只读 | 显示同步/冲突；按能力开放写入 | 不依赖 WASM hydration；浏览器不是本机文件 provider |
| Desktop | 一个嵌入 Runtime，本地编辑与只读远程源 | 自有 Source 离线副本 | Windows/Linux/macOS 分别验证目录、锁、watcher 和物化 |
| Mobile | 认证远程客户端，只读与显式缓存 | 应用沙箱内离线副本、前台重连同步 | 不假设桌面目录 API；不承诺无限后台常驻 |
| CLI/MCP/API | 同一 Source 选择、typed 请求和错误 | 同一冲突裁决/同步状态接口 | MCP 不固定为唯一默认源，不自行重解释写语义 |

移动端离线写是完整目标的独立交付门槛，不能由“HTTP 客户端编译成功”代替。采用平台许可的任务调度，后台受限时明确显示尚未同步；应用恢复前台必须恢复 durable 队列。

共享 ViewModel 至少保留对象地址、revision、有效能力及缓存/同步状态。共享 UI 可以有不同运行时，但不能丢弃身份和 revision 后重新拼造写请求。Runtime 的 cache、watcher、Source 生命周期只有一个所有者；本机存在多个进程时遵循第 7 节写入协调。

## 11. conex 适配性与上游需求

### 11.1 当前实现判断

- 可用于受限只读 fs/HTTP catalog 连接；当前 HTTP catalog 不是通用 HTTP 或 Notez provider。
- Host 有 P1 store/router 接线，不能再称“全部只有离线库”；但 agent CLI 仍未建立真实反连，Source wire 仍无写入。
- `blob/*` 等路径的 schema 校验不能代替授权；当前 Broker 分流绕过普通 Host 调用入口，blob 路径丢弃 claim，需先修复。
- 当前 source/read 是 text+CID，最大正文限制 256 KiB；不能据此声明 PDF/Office 附件和任意大笔记完整支持。
- `invoke_many` 当前串行共用 deadline；“先慢后快”可能饿死后续源，不能仅依据部分结果类型宣称故障隔离完成。
- sync、发现和零知识复制仍是设计范围，不是已验证服务。

## 12. 交付顺序与验收门禁

N0–N4 为 Notez 切片，和 conex 的 P0–P4 无编号对应关系。每个切片单独编写实施计划；下面是范围和退出标准，不是已经完成的任务。

| 切片 | 交付 | 前置与退出标准 |
|---|---|---|
| N0：安全与本地正确性 | 统一授权、来源 allowlist、单 Runtime、写入协调与恢复、创建/裁决过协议 | 未授权 Web/raw/API/MCP 均拒绝；同源跨进程写冲突可见；任何失败不丢草稿，不虚报成功 |
| N1：多源身份与注册 | Space/Source 分离、稳定对象键、单配置真相、权限感知 Source 列表 | 本地两个 Source 同名文件不冲突；同 Source 跨 Space 保持同地址；卸载不删除正文 |
| N2：只读 conex 连接 | Notez 消费 fs/catalog；分页、缓存、逐源状态；桌面/Web/认证移动端共享读语义 | 一个真实远端源成功、一个失败时结果不混淆；超限和无稳定身份的限制明确显示 |
| N3：远程互联完整化 | 独立交付 Notez provider、附件、条件写、私有反连 | 按需依赖 CX-01/04/05/06/09/10；未交付能力继续明确关闭，不要求所有子项一起发布 |
| N4：自有 Source 多副本 | conex P3-a 接入、笔记 payload、离线队列、冲突 UI、桌面及移动物化 | 依赖 N0/N1 和 CX-07；不依赖 ACP、Anytype 或目录发现；完成下方故障矩阵 |

N2 可在 N1 身份的弱能力标记下接入路径型只读源，但不得对其承诺移动不变引用。N4 与 N3 的非复制子项可独立推进；私有网络无法直连时，才把反连/中继加入具体部署前置。

### 12.1 完整目标验收矩阵

| ID | 场景 | 必须观察到的结果 |
|---|---|---|
| A01 | 两个本地源、一个远程源同时注册 | 三个来源独立可见、可定位；默认源不是唯一可用源 |
| A02 | 同源跨 Space，独立源内容相同 | 前者同身份；后者不自动合并 |
| A03 | 文档改名、正文变更、外部含歧义移动 | 前两者身份不变；歧义显式待确认，不误绑 |
| A04 | 匿名/越权调用 Web/raw/API/MCP，猜服务器路径 | 统一拒绝；无文件读取/开库等越权副作用 |
| A05 | 一个源超时、一个源有结果、分页中断 | 成功结果保留；逐源状态明确；本地投影不误删 |
| A06 | 受协调的 Notez 写入者并发更新/创建、文件已写后索引失败、响应丢失 | 仅合法写入成功；恢复不重复执行；源提交与索引状态可区分；外部非协作写入不虚报强 CAS |
| A07 | 三设备离线修改同一正文、不同正文 | 同对象保留并发版本；不同对象独立收敛 |
| A08 | 删除与修改并发、移动目录形成环、跨平台同名碰撞 | 不丢版本、不复活、不写出目录；结构冲突可裁决 |
| A09 | 冲突裁决后再同步 | 所有设备得到同一 resolution 历史和状态，旧版本按保留策略仍可追溯 |
| A10 | 重复/乱序/缺父/缺块、在接收和应用之间崩溃 | 幂等恢复；依赖完整前不错误推进 applied cursor |
| A11 | 修改一次文件后多个 watcher 周期、远端物化触发 watcher | 无无限 push 回环；失败队列重启后仍可见且可恢复 |
| A12 | 猜 CID/句柄、权限撤销后离线提交、恶意发现候选 | 不跨权限读写；本地分支不丢；发现不扩大信任 |
| A13 | 大附件中断续传、损坏块、pin 与 GC 并发 | 原字节一致；坏块拒绝；未完整时不报告已提交 |
| A14 | Windows/Linux/macOS 与移动沙箱读取同一组对象 | 地址/revision/错误一致；物化差异可见，不把单平台编译当验收 |
| A15 | 手机休眠/重启、无网编辑后前台恢复 | 队列不丢、状态准确；无后台常驻时也可最终同步 |
| A16 | 恢复正文、身份目录、复制历史、密钥的备份 | 可识别缺失项；只有 key/heads 而无内容时不能报告恢复成功 |

所有验收都需要运行真实路径并保留结果；仅新增 schema、mock 回声、库函数 happy path 或构建成功不能替代上述门禁。
