#+title: Notez 联邦知识平台设计
#+date: 2026-08-02
#+STARTUP: showeverything

* 1. 定位与目标

Notez 是本地优先、可联邦的全功能知识管理平台，而不是一种新的
笔记文件格式或某个云端服务的替代品。它以一个可组合的统一知识
协议连接本地文件、远程服务、客户端与 AI Agent。

产品优先级：

1. 个人知识管理体验；
2. MCP/AI 与代码文档能力；
3. Notion、Anytype 等远程来源的双向同步；
4. 跨服务端、跨设备的联邦聚合。

本地 Markdown 与 OrgMode 是默认主存储：离线可用、内容可见、无需
依赖 Notez 才能继续访问。外部服务是来源适配器，不是系统唯一的
真相来源。

* 2. 本质问题与架构决策

** 2.1 本质问题

需要同时保留文件主权、接入异构远程服务、让同一知识跨空间组合，
并使人类客户端和 Agent 以相同规则读写。将任一笔记格式、某个
服务商或某个客户端作为中心都会破坏其中至少一项。

** 2.2 决策：虚拟联邦知识图谱

采用“虚拟联邦知识图谱”。=Knowledge Object= 有稳定全局 ID；同一
对象可被多个空间引用；文件、远程页面、卡片和 Agent 上下文包都
是该对象在不同来源或界面中的投影。领域协议稳定，来源适配器和
客户端实现可替换。

不采用：

- 单一中心数据库：实现较快，但会削弱文件可移植性并加剧服务锁定；
- 纯文件加 Git：可靠但难以支持远程双写、结构化项目管理和丰富客户端。

* 3. 核心信息模型

| 概念 | 责任 | 关键约束 |
|---+---+---|
| =KnowledgeObject= | 笔记、任务、项目、摘要、代码符号、网页摘录等统一对象 | 具备稳定全局 ID、内容块、元数据、关系和版本 |
| =Space= | 访问、组织、同步和授权边界 | 不是对象的唯一所有者；同一对象可在多个 Space 被引用 |
| =Source= | 文件、远程 API、网页或联邦节点 | 声明读、写、附件、增量同步、冲突处理等能力 |
| =Projection= | 特定来源或视图中的对象呈现 | 可映射为 Org/Markdown、远程页面、列表、看板或上下文包 |
| =Change= | 可追踪的领域变更事件 | 先本地持久化，再投递；失败、冲突和授权结果可检查与重试 |
| =Relation= | 对象、代码、空间和来源的连接 | 关系有类型、方向、证据、创建者和版本 |

Space 对对象只保存空间语义，例如分类、排序、标签、视图和访问
授权；不得复制对象正文。这样一个项目知识对象可以同时出现在
个人空间、项目空间和归档资源视图。

* 4. 边界与统一协议

Core 提供唯一领域 Use Case 层。Web、桌面、移动端、CLI、HTTP API
和 MCP 都经由该层执行；来源 Adapter 只负责读取、转换和回写。
客户端或 MCP 不得直接依赖 Org、Markdown、Notion 或 Anytype 的
内部格式。

Source Adapter 至少声明：

- =read=、=write=、=attachments=、=incremental_sync=、=conflict_details=
  等能力；
- locator 与远程 revision 的映射；
- 可转换的对象/块/关系范围；
- 不支持或有损回写时的明确错误。

公开接口统一暴露对象、空间、关系、查询、变更、同步任务和授权
结果，而非泄漏具体 Adapter DTO。

* 5. MCP、API、CLI 与 Agent

** 5.1 能力

MCP、HTTP API 和 CLI 共用领域协议，提供：

- 发现与查询：列出可访问的空间、来源与类型；全文、标签、关系、
  时间、代码符号与项目上下文检索；
- 理解与索引：扫描 Git 工作区及代码注释，建立“符号—文件—实现—
  设计—决策—任务”关系；按变更范围生成上下文包；
- 摘要：创建和更新可追溯的 summary，保留来源对象、生成者、输入
  revision 与过期状态；
- 受控写入：创建、编辑、关联对象，更新任务与摘要，并交由来源
  Adapter 回写；
- 审计：记录调用方、授权来源、影响对象、变更集、同步状态与修订入口。

** 5.2 授权

写入不是全局开关。策略判断维度为：

=Principal × Space × Source × Action × Scope=

令牌或 API Key 只标识调用方；服务端策略决定权限。例如某 Agent
可在个人空间更新项目摘要和任务、只能读取 Notion，且不能写入
生产空间的文件。拒绝应稳定返回机器可读原因，并写入审计记录。

** 5.3 代码引用协议

使用稳定 URI，供代码注释、文档、CLI 和 MCP 共用：

#+begin_example
notez://object/<global-id>
notez://query/<saved-query-id>
notez://code/<repo>/<symbol-id>
#+end_example

其中 =object= 直接定位知识对象，=query= 定位动态上下文，=code= 定位
代码符号。索引器从注释和代码解析结果建立证据化 Relation；Agent
可从一个符号检索设计、实现、相关任务和当前 summary，并将实现
记录回写至已授权空间。

* 6. 客户端、PARA 与看板

以 Dioxus 实现共享客户端体验，优先覆盖 Web、Windows、Linux、macOS
与 iOS；平台层只补充文件访问、通知、系统分享和后台同步等能力。

主要界面：

- 左侧：Space 切换、来源状态、收藏、收件箱和 PARA 入口；
- 主区：块编辑/阅读，可在大纲、关系、文件原文和属性间切换；
- 右侧：反向链接、关联代码、活动、同步状态和 Agent 审计；
- 全局命令栏：查询、创建、引用、移动与调用已授权工作流。

PARA 是 Space 内的分类关系与保存查询，不是四个互斥文件夹。对象
可同时属于 Project、Area 或 Resource；Archive 是可恢复的状态或
投影。看板是保存查询的投影，例如“项目 X 中进行中的任务”；拖动
卡片改变统一任务对象状态，而非创建副本。

* 7. 本地优先同步与冲突

1. 所有操作先写本地变更日志，离线可用；
2. 同步引擎按 Source capability 将变更转成文件修改、远程 API
   调用或联邦节点消息；
3. 能安全合并时保留来源 revision 与合并证据；不能合并时生成冲突
   对象，保留双方版本，供用户或已授权 Agent 决定；
4. 状态必须可见：已同步、等待远程、冲突、无权限、来源不支持。

系统绝不静默覆盖远程或本地版本。联邦节点即使离线或时钟不可靠，
也通过可重放 Change 与显式冲突而非隐含“最后写入获胜”来演进。

* 8. MVP 路线

** MVP-1：本地知识底座

多 Space 聚合、Markdown/OrgMode 双向编辑、统一对象 ID、关系与附件、
离线变更日志。验收为：同一对象能在两个本地 Space 被引用，修改
可追踪并可同步，原始文件仍可脱离 Notez 使用。

** MVP-2：Agent 与代码知识

提供统一 MCP/HTTP/CLI、授权策略、代码注释和符号索引、上下文查询、
summary 与受控写回。验收为：Agent 可由符号获得设计、任务、实现和
摘要，并在授权范围内写回决策、任务和实现记录；未授权操作被拒绝
且可审计。

** MVP-3：个人客户端

交付 Space、编辑器、搜索、反向链接、PARA、查询驱动看板和同步/审计
面板。验收为：日常使用可完整管理本地知识；看板拖动更新同一对象，
并按主 Source 回写。

** 后续扩展

Notion/Anytype 双向 Adapter、网页摘录、跨服务端发现与授权，以及更深
的平台原生能力。新增来源必须只增加 Adapter 与 capability 声明，
不改变 Core、MCP/API/CLI 或客户端的领域语义。

* 9. 非目标与风险控制

本轮不承诺任意格式的完美无损双向转换、自动解决所有远程冲突、
多人实时协作编辑，或映射 Notion/Anytype 的全部专有功能。适配器必须
显式报告其支持范围和有损行为。

主要风险是把“统一模型”误做成“最低共同能力模型”。缓解原则是：
Core 只稳定表达对象、关系、变更和授权；来源专有能力留在 capability
声明与扩展字段中，不能倒灌为全系统必选字段。

* 10. 架构验收场景

1. 一个对象在多个 Space 被引用而不复制正文；
2. 本地离线变更可被观察、重试和同步，不静默丢失；
3. 同一 Use Case 在 MCP、API、CLI 和客户端中产生一致授权与结果；
4. 从一个代码符号可解析到设计、任务、实现、关系证据和 current summary；
5. Agent 只能在授权 Scope 内改写知识库，所有写入带审计与 revision；
6. 新增 Notion/Anytype Adapter 不要求修改统一领域语义；
7. PARA 和看板均为对象的投影，改变分类/状态而非创建内容副本。
