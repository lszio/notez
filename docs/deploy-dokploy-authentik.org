#+title: Dokploy 部署 + authentik 认证 runbook

#+begin_quote
文件分工：=docker-compose.yml= 本地开发（loopback）；=docker-compose.dokploy.yml= dokploy 部署（Traefik + authentik forward-auth）。本文以 dokploy 实例 =dokploy.lszio.space= 与 authentik =auth.lszio.space= 为准。
#+end_quote

* 认证模型（两层，互不依赖）

| 层 | 保护对象 | 机制 | 配置来源 |
|---+---------+------+---------|
| 代理层 | 浏览器访问的全部路由（SSR UI + 静态资源） | Traefik forward-auth，未登录 302 到 authentik | dokploy 域名中间件 =authentik-auth@file= |
| 应用层 | =/api/v1/*= 与 =/mcp= | 应用内 OIDC bearer 校验（JWKS、iss/aud/exp） | =NOTEZ_API_OIDC_ISSUER= / =NOTEZ_API_OIDC_AUDIENCE= |

浏览器 UI 不直接调 =/api/v1=（数据走 SSR server functions），所以两层各管各的；机器客户端（CLI/MCP）用同一个 provider 签发的 access token 走 bearer。

应用侧的公开 bind 拒绝规则（=crates/api/src/config.rs=）由 OIDC 环境变量满足，容器才能启动。

* 已就绪的基础设施（不必重建）

- 全局 Traefik 动态配置已定义中间件 =authentik-auth=（forwardAuth → authentik embedded outpost =http://infra-authentik-kzthsk-server-1:9000/outpost.goauthentik.io/auth/traefik=，带 X-authentik-* 回传头），helloworld（=hello.lszio.space=）已用它验证过。
- embedded outpost 随 authentik server 进程发布；新建 proxy provider 后自动生效，无需动 outpost。
- dokploy 已配置 GitHub provider（Dokploy GitHub App），git 源部署可直接用。

* authentik 控制台

1. *Provider*：Directory → Providers → Create → =Proxy Provider=。
   - Authorization flow: =implicit-consent=。
   - Mode: =forward_auth (single application)=。
   - External host: =https://notez.lszio.space=。
   - 记下 slug（下称 =<provider-slug>=）与 client id（=<client-id>=）。
2. *Application*：绑到上面的 provider，slug 建议 =notez=。
3. 访问控制在 Application 的 Policy / Group 绑定上做（不绑 = 所有 authentik 用户可见）。

* dokploy 部署

1. Project =App= → Create Service → *Compose*：
   - Git source：=lszio/notez=，branch =dev=，compose path =docker-compose.dokploy.yml=。
   - Environment（缺一 compose 拒启，fail-closed）：
     #+begin_example
     NOTEZ_API_OIDC_ISSUER=https://auth.lszio.space/application/o/<provider-slug>/
     NOTEZ_API_OIDC_AUDIENCE=<client-id>
     #+end_example
   - issuer *必须带尾部斜杠*（与 authentik discovery 的 =issuer= 配平最稳）。
2. Domain：给 =web= 服务绑 =notez.lszio.space=，HTTPS + letsencrypt，port =3030=，middlewares 填 =authentik-auth@file=。
3. Deploy。构建约 10 分钟（Rust release 全量编译，首次无缓存）。

* 验证

#+begin_example
# 未登录浏览器访问 → 应 302 到 authentik 登录页
curl -si https://notez.lszio.space/ | head -3

# healthz 双层公开，IdP 挂了也要 200
curl -s https://notez.lszio.space/api/v1/healthz

# 应用层 bearer 校验：无 token 应 401
curl -s -o /dev/null -w '%{http_code}\n' https://notez.lszio.space/api/v1/dispatch -X POST
#+end_example

机器客户端：用 provider 的 client-credentials（或用户登录后的 access token）请求 =POST /api/v1/dispatch=，带 =Authorization: Bearer <jwt>= 与 =X-Notez-Source=。

* 故障速查

- *起不来：=set NOTEZ_API_OIDC_ISSUER= 之类* → compose 的 =:?= 变量没配。
- *起不来：refusing to serve without authentication* → OIDC 两个变量没进容器（检查 Environment 作用域）。
- *302 循环 / 403* → Proxy Provider 的 External host 与 =notez.lszio.space= 不一致，或 outpost 未含该 application。
- *forward-auth 502* → Traefik 到 =infra-authentik-kzthsk-server-1:9000= 不可达（容器名变了：以 authentik compose 的实际 server 容器为准）。
- *API 401 但浏览器正常* → audience 不配：=NOTEZ_API_OIDC_AUDIENCE= 必须 = provider client id。
