#+title: Notez
#+STARTUP: showeverything

Notez is a local-first, Org-mode-first knowledge federation engine written in Rust.

* Core Principles

1. *Files are authoritative*: Native Org and Markdown files are the single source of truth. SQLite databases, knowledge graphs, and projections are completely disposable and rebuildable from original files.
2. *Org & Markdown support*: Org TODO states, properties, headings, and ID links, plus Markdown frontmatter, HTML comment heading IDs, and WikiLinks (=[[...]]=).
3. *Unified resource algebra*: All document nodes, headings, and attachments use stable =ResourceRef= identifiers (=document:<ULID>=, =heading:<ULID>=, =attachment:<ULID>=). Paths and titles are not identities. See [[file:docs/architecture.org][Architecture]] and [[file:docs/link-protocol.org][Link Protocol]] for details.
4. *Rebuildable projection*: Deleting =.notez/index.sqlite= is always safe after stopping Notez; running =notez space rebuild= or =notez source sync= reconstructs the projection byte-for-byte.
5. *Extensible Configuration*: Declarative configuration across global XDG scope and workspace-local space definition. See [[file:docs/configuration.org][Configuration]].

* Workspace Layout

#+begin_src text
crates/
├── core/         Engine<S> + Dispatcher, domain, document, source, sync, artifact, storage
├── protocol/     Typed Request/Response DTO + JSON Schema
├── composition/  Shared Runtime (engine cache + watcher) for every host process
├── api/          notez-api: HTTP transport /api/v1/* + auth + remote NotezClient
├── mcp/          notez-mcp: rmcp ServerHandler, transport-agnostic
│                 ├── default: stdio (notez mcp serve)
│                 └── feature http: streamable-HTTP /mcp via rmcp transport-streamable-http-server
├── preview/      SSR/CLI preview builders (separate from core)
├── cli/          notez binary entry point (commands + handlers, delegates mcp to notez-mcp)
├── adapters/     orgmode + markdown parser/reader crates
packages/
├── ui/           Shared Dioxus rendering core + design system + Backend trait
│                 └── workspace.rs: NzShell / NzTree / NzDocBody + tree model,
│                     reused by web (SSR), desktop and mobile (native)
├── web/          Dioxus SSR workspace + host assembly
│                 ├── app/: pages rendered from data read during SSR
│                 │        (no #[server] functions, no hydration)
│                 ├── data/: space/file/document access + utility endpoints
│                 ├── default mode: UI + /api/v1 + /mcp (one shared Runtime)
│                 └── NOTEZ_MODE=server: headless api + mcp only
├── desktop/      Dioxus desktop + EmbeddedBackend (composition Runtime, no HTTP)
└── mobile/       Dioxus mobile (future HttpBackend via notez-api::NotezClient)
#+end_src

* CI & Docker

GitHub Actions workflow: =.github/workflows/ci.yml=. Runs on push/PR to
=main= / =dev= with three jobs:

- =test= — =cargo build --workspace --all-targets= + =cargo test --workspace=
- =lint= — =clippy= (warnings reported) and =rustfmt --check= (report-only
  until a one-shot =cargo fmt --all= normalisation lands)
- =docker= — builds the web server image and smoke-tests that it responds

Run the web SSR server in Docker:

#+begin_src bash
docker compose up -d          # build + start, http://localhost:3030
# or
docker build -t notez-web:latest .
docker run --rm -p 3030:3030 notez-web:latest
#+end_src

The server binds =IP=0.0.0.0= / =PORT=3030= inside the container. Mount a
volume at =/data= to persist spaces registered through the web picker
(=docker-compose.yml= does this via the =notez-data= volume). Optional
=NOTEZ_SPACE_ROOT=/data/space= pins a default space root.

* CLI Usage

** Space & Resource Management

Scans =.org= and =.md= documents into the SQLite projection store:
#+begin_src bash
notez --space /path/to/space scan
#+end_src

Search resources by kind or title substring:
#+begin_src bash
notez --space /path/to/space query --kind heading --title-contains "sync" --json
#+end_src

Fetch full resource metadata and properties:
#+begin_src bash
notez --space /path/to/space read heading:01J00000000000000000000001 --json
#+end_src

Deletes index cache and rescans space from raw files:
#+begin_src bash
notez --space /path/to/space space rebuild
#+end_src

** Links & References

Resolves a ULID, exact =ResourceRef=, file path locator, or title query:
#+begin_src bash
notez --space /path/to/space resolve "01J00000000000000000000001"
#+end_src

List occurrences and resolved links for a given resource:
#+begin_src bash
notez --space /path/to/space link list document:01J0000000000000000000000A
notez --space /path/to/space link resolved document:01J0000000000000000000000A --json
#+end_src

Fine-grained paragraph and code block entities use =block:<ULID>= references:
#+begin_src bash
notez --space /path/to/space query --kind block --json
#+end_src

** Task & PARA Workflow

Notez unifies Task and PARA (Projects, Areas, Resources, Archives) workflows. Every PARA node can act as a container for nested tasks, and a Project itself can bear a task state (e.g. =TODO= or =NEXT=).

Overview of PARA structures with their nested tasks:
#+begin_src bash
notez --space /path/to/space task para
#+end_src

Agenda view of scheduled, deadline, or actionable items:
#+begin_src bash
notez --space /path/to/space task agenda --json
#+end_src

Atomic Org TODO state transition with CLOSED timestamp and LOGBOOK entry:
#+begin_src bash
notez --space /path/to/space task transition heading:01J00000000000000000000001 --to DONE
#+end_src

** Federation & Data Sources

Mount external sources such as Obsidian Vaults or Git repositories:
#+begin_src bash
notez --space /path/to/space source add --id vault_src --kind obsidian --path /path/to/vault --read-only
notez --space /path/to/space source list --json
notez --space /path/to/space source sync --json
#+end_src

Mount Anytype sources and execute atomic writeback mutations:
#+begin_src bash
notez --space /path/to/space source add --id anytype_src --kind anytype --path /anytype/path --read-only
notez --space /path/to/space source writeback --id anytype_src --r-ref heading:01J00000000000000000000001 --payload "Updated Title"
#+end_src

** Attachments & Content Extraction

Add attachments, run text/metadata extraction jobs, and query extracted segments:
#+begin_src bash
notez --space /path/to/space attachment add --path /path/to/file.txt --mime text/plain
notez --space /path/to/space attachment extract attachment:01J00000000000000000000001
notez --space /path/to/space attachment segments attachment:01J00000000000000000000001 --json
#+end_src

** Agent Context & Skill Derivation

Create and list communities bound by selectors:
#+begin_src bash
notez --space /path/to/space community create --id dev_comm --name "DevSync" --title-contains "sync"
notez --space /path/to/space community list --json
#+end_src

Derive =summary=, =llms.txt=, =context-pack=, or =skill-ir= artifacts:
#+begin_src bash
notez --space /path/to/space derive --community dev_comm --recipe summary --json
#+end_src

Export a standalone =SKILL.md= package containing prompt directives and references:
#+begin_src bash
notez --space /path/to/space skill export --community dev_comm --description "DevSync Prompt Skill" --out /path/to/skill
#+end_src

** P2P Sync & Diagnostics

Synchronize notes offline between devices via a shared folder (=heads/=, =manifests/=, =objects/=, =tombstones/=):
#+begin_src bash
notez --space /path/to/space_a sync push --actor device_a --folder /path/to/shared
notez --space /path/to/space_b sync pull --actor device_b --folder /path/to/shared
notez --space /path/to/space_b sync conflicts --json
#+end_src

Sync via Relay server (the folder-based transport is the default):
#+begin_src bash
notez --space /path/to/space sync relay --id anytype_src
#+end_src

Run space integrity checks (broken links, missing files, corrupt indexes):
#+begin_src bash
notez --space /path/to/space space doctor --json
#+end_src

List background jobs and check artifact freshness:
#+begin_src bash
notez --space /path/to/space job list --json
notez --space /path/to/space artifact stale --json
#+end_src

** MCP Integration

Exposes query, resolve, read, inspect, agenda, task transition, attachment, community, derive, skill export, source management, and sync tools over stdio using newline-delimited JSON-RPC:
#+begin_src bash
notez --space /path/to/space mcp serve
#+end_src

** HTTP Protocol API

The =notez-api= crate exposes a typed JSON protocol at =/api/v1/*=. The
=web= binary mounts it beside the SSR UI; the =cli= hosts the same
router standalone via =notez serve=.

#+begin_src bash
# Standalone server (CLI):
notez serve --bind 127.0.0.1:8700 --source /path/to/space
curl http://127.0.0.1:8700/api/v1/healthz
curl -X POST -H 'Content-Type: application/json' \
  --data '{"op":"query_resources","title_contains":"sync","limit":5}' \
  http://127.0.0.1:8700/api/v1/dispatch
#+end_src

Auth contract (env vars): =NOTEZ_API_TOKEN= (shared secret) or
=NOTEZ_API_OIDC_ISSUER= + =NOTEZ_API_OIDC_AUDIENCE= (JWT validation
against the identity provider's JWKS). Public binds are refused without
one of them; loopback binds default to anonymous.

** MCP over streamable HTTP

Same =notez-mcp= handler serves stdio (local agent) and streamable-HTTP
(remote agent reaching a running notez server) when the =http= feature
is enabled. The web host mounts it at =/mcp= behind the same bearer or
OIDC middleware the API uses:

#+begin_src bash
IP=127.0.0.1 PORT=8765 /path/to/web-binary &
curl -X POST -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  --data '{"jsonrpc":"2.0","id":1,"method":"initialize",
           "params":{"protocolVersion":"2025-11-25","capabilities":{},
                     "clientInfo":{"name":"smoke","version":"0"}}}' \
  http://127.0.0.1:8765/mcp
#+end_src

** Host modes (web binary)

The =web= binary serves both web UI + API + MCP, or a headless server
mode, depending on =NOTEZ_MODE=:

#+begin_src bash
# default: workspace UI + /api/v1 + /mcp over one shared composition Runtime
IP=127.0.0.1 PORT=8765 ./web-binary

# headless: only /api/v1 + /mcp, no UI
NOTEZ_MODE=server IP=127.0.0.1 PORT=8765 ./web-binary
#+end_src

** Workspace UI

The default mode serves a Dioxus-rendered workspace (SSR, no hydration):
a collapsible *directory tree* in the sidebar, one content column, an
editor at `?edit=1` with a formatting toolbar and a live preview pane,
and inline previews for attachments (images, PDF, Office, CSV,
archives). The presentational pieces (=NzShell=, =NzTree=, =NzDocBody=)
live in =packages/ui= so desktop and mobile render the same workspace.

- *Scan / Refresh* sit in the sidebar footer; Scan re-indexes the space
  and returns to the page you were on.
- A file changed outside the editor raises a "changed on disk — reload"
  pill (the page polls a cheap mtime fingerprint).
- Saving is revision-guarded (content sha256); a conflict keeps your
  text, shows a warning and switches to the on-disk revision so the next
  save is a deliberate overwrite.
- Landing: `/` redirects to the configured default source, otherwise it
  shows the space picker (=POST /register= writes
  =~/.config/notez/config.toml=).

#+begin_src bash
just web                # release build + run (port 8765); DEV=1 for debug
#+end_src

** Embedded Dioxus clients

=packages/desktop= embeds the engine in-process via the composition
=Runtime=. =packages/mobile= is a Dioxus mobile shell that will use
=notez-api::NotezClient= to talk to a running =notez= host. Both
surfaces share =packages/ui= design tokens and primitives; the web
workspace UI is independent of them.

* Exit Codes


- =0=: Success
- =2=: Invalid request or argument error
- =3=: Resource not found
- =4=: Ambiguous resolve match
- =5=: Internal application failure or I/O error
